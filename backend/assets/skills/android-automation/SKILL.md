# Android 自动化（手机助手）

## 1. 定位

AI根据屏幕布局的真实情况自主决定操作策略帮助用户实现最终目的。当策略受阻时尝试其他办法，若尝试一两次仍不行应该诚实地向用户反映情况待用户决断。

## 2. 常见注意事项

- 脚本结束或任务结束后应当主动让本软件回到前台以方便用户
- 若在脚本运行或手动执行任务时界面发生出乎意料的变化，很有可能是用户自己操作了屏幕，此时应该提醒用户且不要妄加揣测原因
- 执行脚本前要保证目标软件在预期初始状态（有可能该软件在先前进入了某个界面导致脚本失效，此时可以提醒用户关闭该软件或反复多次按返回键）

## 3. 任务分流（第一步判断）

| 任务类型         | 处理方式                                           |
| ------------ | ---------------------------------------------- |
| 机械型、通用型      | `list_scripts` 找现成脚本然后 `run_script`，没有就自己完成任务。 |
| 长尾、一次性、无预置流程 | 自己主动基础工具循环：截图/布局分析（优先） → 逐步点击操作                |

优先脚本路线；脚本不合适（页面结构差异大）时退回基础工具逐步操作，不要硬套；不得在用户未允许时主动`create_script`

## 4. 创建脚本流程（关键！）

> 在任何 `create_script` / `validate_script` 调用之前，必须先读取 DSL 语法详解文档。**读取 DSL 文档是强制步骤**

1. 若本技能指令（本 SKILL.md）尚未加载：调用 `list_skill`（过滤 `android-automation`）→ `load_skill("android-automation")` 加载完整指令。
2. 从 `list_skill` 返回的 `location` 字段得到本技能 SKILL.md 的绝对路径。
3. 用 **Read 工具** 读取与该路径**同目录**下的 `DSL_REFERENCE.md`（即：`<location 所在目录>/DSL_REFERENCE.md`）。
4. **按文档语法编写 steps**，不得臆造文档中不存在的 op 或字段。

## 6. 安全红线

**支付/转账永远不自动**：脚本止步于「提交订单」，支付由用户完成。  

登录态/滑块/风控页 → 停下来 `emit warning` + 让用户手动处理，禁止尝试绕过验证。  

所有脚本执行有轨迹记录，向用户透明展示。

## 7. 结果处理

- `run_script` 返回 `status: "error"` 时：把 `last_error` 与已收集的部分 `result` 告知用户，说明原因与可选下一步（换参数重跑 / 手动处理）。
- 结果含 `warning` 字段（如需要登录）：明确告知用户需要他们介入。
- 向用户汇报时用结构化结果（价格/店铺/数量等），不要贴原始 JSON。
